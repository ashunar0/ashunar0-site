## この記事について

この記事では、Mac で Ruby on Rails の開発環境を作ります。

### インストールするもの

| 道具  | 役割                                 |
| ----- | ------------------------------------ |
| rbenv | Ruby のバージョンを管理する道具      |
| Ruby  | Rails を動かすための言語             |
| Rails | Web アプリを作るためのフレームワーク |

Mac には最初から Ruby が入っていますが、これは macOS 自身が使うためのものです。バージョンが古く、変更するとシステム側に影響する可能性があるため、これには手を触れません。代わりに rbenv を使って、自分用の Ruby を別に用意します。

rbenv を挟むのは、プロジェクトごとに必要な Ruby のバージョンが違うことがあるためです。Rails のプロジェクトは使う Ruby のバージョンを指定して作られるので、あとから切り替えられる状態にしておくと困りません。

### 前提

Homebrew を使います。エディタは VSCode を想定しています。まだの場合は先に済ませてください。

### 所要時間

30 分程度です。Ruby のインストールに時間がかかります。

## 1. rbenv を入れる

```bash
brew install rbenv
```

Ruby をインストールするための `ruby-build` も一緒に入ります。

### シェルの設定を追加する

rbenv は、インストールしただけでは動きません。ターミナルを開いたときに rbenv を読み込む設定を追加します。

```bash
echo 'eval "$(rbenv init - zsh)"' >> ~/.zshrc
```

この 1 行を入れておくと、ターミナルを開いたときに「rbenv で入れた Ruby を使う」という状態が自動的に作られます。これが無いと、あとで Ruby を入れても Mac 標準の Ruby が使われたままになります。

### 入ったか確認する

**ターミナルを一度閉じて、開き直してください。**

新しく開いたターミナルで以下を実行します。

```bash
rbenv --version
```

`rbenv 1.x.x` のように表示されれば完了です。

## 2. Ruby を入れる

Ruby 3.4.10 を入れます。

```bash
rbenv install 3.4.10
```

**このコマンドは 5 〜 15 分かかります。** Ruby を配布されたファイルから組み立てる処理が走るためです。表示が止まったように見えても、終了させずに待ってください。

インストールが終わったら、入れた Ruby を使う設定にします。

```bash
rbenv global 3.4.10
```

`global` は「特に指定がなければこのバージョンを使う」という意味です。

### 入ったか確認する

```bash
ruby -v
```

`ruby 3.4.10 ...` のように表示されれば完了です。

もし `ruby 2.6.x` や `ruby 3.x.x` など、入れた覚えのないバージョンが表示された場合は、Mac 標準の Ruby が使われています。手順 1 のシェル設定が反映されていないので、ターミナルを閉じて開き直してから、もう一度確認してください。

### バージョンが見つからないと言われた場合

`rbenv: version '3.4.10' not found` のように表示されることがあります。これは rbenv が知っている Ruby の一覧が古いために起きます。次のコマンドで更新してから、もう一度インストールしてください。

```bash
brew upgrade ruby-build
```

なお、インストールできるバージョンの一覧は次のコマンドで確認できます。

```bash
rbenv install -l
```

## 3. Rails を入れる

Rails は gem（Ruby のライブラリ）として配布されているので、`gem` コマンドで入れます。

```bash
gem install rails
```

数分かかります。Rails 本体だけでなく、Rails が必要とする多数の gem が一緒に入るためです。

### 入ったか確認する

```bash
rails -v
```

`Rails 8.x.x` のように表示されれば完了です。

`rails: command not found` と表示された場合は、次のコマンドを実行してから、もう一度確認してください。

```bash
rbenv rehash
```

これは、新しく入ったコマンドを rbenv に認識させるための操作です。

## 4. アプリを作って起動する（任意）

実際に Rails アプリを 1 つ作って、動くところまで確認します。この手順は飛ばしても問題ありません。

アプリを作りたい場所に移動してから実行します。

```bash
rails new rails-test
```

`rails-test` がフォルダ名になります。**数分かかります。** アプリの骨組みが作られたあと、必要な gem がまとめてインストールされるためです。

作られたフォルダに移動して、開発サーバーを起動します。

```bash
cd rails-test
rails s
```

`s` は `server` の省略形です。`rails server` と書いても同じです。

次のような表示が出ます。

```
=> Booting Puma
=> Rails 8.x.x application starting in development
* Listening on http://127.0.0.1:3000
```

ブラウザで <http://localhost:3000> を開いてください。Rails のロゴが表示された画面が出れば成功です。

### サーバーを止める

ターミナルで `Ctrl + C` を押すと止まります。Mac でも `Command` ではなく `Ctrl` です。

再開したいときは、`rails-test` フォルダの中で `rails s` をもう一度実行してください。

### VSCode で開く

別のターミナルを開いて、`rails-test` フォルダで次を実行すると VSCode で編集できます。

```bash
code .
```
